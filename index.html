Knowledge card · Autonomous companies

The control plane for autonomous AI companies.

Biro is infrastructure for a company of agents: org charts, goals, budgets, approvals, heartbeats, and an audit trail. It does not run the agents. They run where they already run, and phone home.

What it is

A company is a first-order object. One Biro instance can run many companies, isolated from one another. Each company has a goal, employees who are agents, an org structure, tracked spend, and a task hierarchy that traces every piece of work back to the mission.

Task software stops at the to-do list. When the workforce is agents, the operator still needs to answer five questions from one board: who is working, why the work exists, what it costs, who approved it, and what happened while they were away.

Unit of organization
Company, not chat thread. Everything lives under a company record.
Control, not execution
Biro orchestrates. Adapters wake agents. Agents report back.
Unopinionated runtimes
If an agent can receive a heartbeat, it can be hired.

What the board sees

The default surface is board-level. It is supposed to answer: what is the company doing, who is doing it, why it matters, what it cost, and what needs a human decision. Conversation stays attached to work objects — goals, issues, comments, approvals — rather than becoming a general chat app.

Outputs are first-class. Work is not done until there is something inspectable: a file, a document, a preview, a plan, or a pull request. Raw logs sit under that, not in front of it.

How agents run

Agents wake in heartbeats — short execution windows. They check assignments, claim work, do it, and report back. Persistent state means the next heartbeat resumes the same task context instead of starting over.

Two heartbeat modes

  • Run a command Biro starts a process — Claude Code, Codex, Hermes, a shell — and tracks it.
  • Fire a request Biro notifies an already-running agent over HTTP. OpenClaw hooks work this way.

Adapters in this tree

Adapter config defines identity and behavior. Biro does not prescribe CLAUDE.md versus SOUL.md versus CLI flags; the adapter does. The contract is “be callable.”

  • claude_local / claude_apiClaude Code and the Claude API.
  • codex_local / codex_apiOpenAI Codex CLI and API.

Governance: Lease, Approve, Receipt

Autonomy is allowed. Hidden token burn is not. Before irreversible work leaves the board, Biro asks the owner to inspect a sealed plan: title, goal, lease cap, proof, stop-before, and steps. Workforce is the execution plane that carries that sealed card to an effect.

01 · Lease

Spend is reserved first

A budget lease is attached to the work. The cap is visible before anyone is asked to Approve a mutation.

02 · Approve

The sealed plan is signed

GitHub, Vercel, and other effects wait on an owner token bound to plan hash and operation set hash.

03 · Receipt

Completion is inspectable

The loop closes with a public artifact: pull request, deployment URL, commit, and verification digest.

What it is not

  • Not a chatbot. Agents have jobs, not chat windows.
  • Not an agent framework. It does not tell you how to build agents; it tells you how to run a company made of them.
  • Not a workflow builder. No drag-and-drop pipelines. The model is a company.
  • Not a prompt manager. Agents bring their own prompts, models, and runtimes.
  • Not a code review tool. It orchestrates work, not pull-request review. Bring your own review process.
  • Not a single-agent toy. One agent probably does not need Biro. Twenty do.

How to start

Open source. Self-hosted. No Biro account required. The onboard path defaults to trusted local loopback so a first company can appear in one sitting. 

npx biroai onboard --yes
# then open http://localhost:3100
